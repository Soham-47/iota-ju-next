\section{Your next task}

Fix the permission problems in PR \#1 and keep the content contract marked DRAFT. Your work can start before the app is built, but Payload-specific checks must wait for Sourasish's P01 foundation.

PR \#1 changes the content contract, access rules and tests. It is not ready to merge yet. The current rules let an Editor change their own email or other fields, and the last Admin check is not safe when two changes happen at once.

\section{Fix the Editor rule}

Editors should be able to change their own approved display name. They must not be able to change their email, role or active status. Password changes must use the approved password reset flow.

Use an explicit list of allowed fields. Do not use a rule that allows every field except role and active.

Add focused tests for these cases:

\begin{itemize}
\item An Editor can change their own approved display name.
\item An Editor cannot change their email, role or active status.
\item An Editor cannot change another person's account.
\item An inactive account cannot write.
\end{itemize}

\section{Protect the last Admin}

The system must always keep at least one active Admin. A count followed by a separate save is not enough. Two Admin requests could both see two Admins and remove each other at the same time.

For now, make the limit clear in the policy and write down the required Payload integration step. When P01 is merged, protect the count and account change together in the Payload operation, then add an integration test for two Admin changes happening at once.

Do not say this is fully safe until the Payload-side check protects the actual write.

\section{Keep B01 as a draft}

The content contract depends on facts from Shreyam's M01 source inventory. Keep it labelled DRAFT. Mark source-dependent fields as pending and list each question with the person who can answer it.

At minimum, keep these ideas clear:

\begin{itemize}
\item A stable source ID is different from a name or URL slug.
\item Draft or published is different from ongoing or completed.
\item Public fields are different from private CMS fields.
\item Unknown dates or identities stay unknown until checked.
\item Project order, reports, real links and media references must be preserved.
\end{itemize}

Ask Sourasish, Pritish and Shreyam to review the fields they use. Do not build B03 collections on a field that the owners have not agreed.
